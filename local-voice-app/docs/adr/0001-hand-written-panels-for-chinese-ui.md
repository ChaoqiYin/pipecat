# 界面中文化靠自建面板，而不是给打包产物打补丁

`@pipecat-ai/voice-ui-kit` 把界面文案写死在打包产物里，既没有 i18n 机制，也只有少数组件留了文案属性出口。为了让面向用户的界面显示中文，我们重建了对话面板、机器人音频面板和连接状态面板，中文文案集中在 `client/src/strings.ts`。Events 调试面板、事件日志正文、事件类型名和 `Debug` 按钮保持英文——面向用户的界面翻，面向开发者的调试面板不翻。

## 考虑过的其他做法

- **只用现成的文案属性**：零成本，但只有角色标签、连接按钮和错误卡片有出口。标签页、跟读模式下拉、输入框占位符、面板标题都改不了，结果是半中半英。
- **引入 `patch-package` 给 `dist` 打补丁**：一次覆盖全部文案且不丢功能，但要把 `^0.11.0` 收紧成固定版本，并在打包产物上做文本 diff，升级库时必然失配。

## 后果

- 对话面板复用库导出的 `Conversation`，逐字高亮、函数调用和 BotOutput 聚合都保留。但 `Conversation` 内部的空态文案没有属性出口，所以消息为空时由 `ChatPanel` 自己渲染空态，有消息时才挂载 `Conversation`。
- 指标标签页无法复用：`Metrics` 组件不在包的 `exports` 字段里，取不到。改为自己订阅 `RTVIEvent.Metrics` 渲染纯文字指标表，代价是丢掉 TTFB 的时间序列折线图。token 用量取自事件载荷上的 `tokens` 字段，它尚未出现在 `client-js` 的类型声明里，代码里加了断言。
- 库里函数调用折叠块的 `Arguments` / `Result` 两个小标题仍无属性出口，保持英文。
